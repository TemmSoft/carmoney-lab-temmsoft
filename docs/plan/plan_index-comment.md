# Plan: добавить комментарий в `backend/public/index.php`

## Не хватает данных

Запрос «добавь комментарий в `backend/public/index.php`» слишком короткий, чтобы
считать его планом. Прежде чем что-то писать, нужно уточнение от заказчика:

1. **Содержание комментария.** Что именно комментируем:
   - весь файл (шапка с назначением точки входа)?
   - строку `require ... autoload.php` (откуда берётся автозагрузка)?
   - строку `AppFactory::create()->run()` (зачем фабрика, а не прямой `new App()`)?
   - поведение при запуске (например, «Slim-приложение собирается в
     `AppFactory`, см. `backend/src/AppFactory.php`»)?

2. **Стиль.** В проекте общая конвенция по комментариям — короткие,
   по делу, без воды. Пример шапки есть в `backend/config/rules.php`
   (docblock + назначение). Нужно ли повторять такой формат здесь
   или достаточно однострочного `// …`?

3. **ID задачи.** Артефакты задач кладутся в `docs/plan/` как
   `plan_<ID>.md` (см. `docs/plan/README.md`). Под какой ID оформить
   план? Если это часть уже идущей задачи — укажите её.

4. **Связь с уже сделанным.** В текущей ветке
   `d1/1.3.1-1.3.4-temmsoft` коммит `a10e115` (`approve_max 60→62.5`,
   кейс «62.0 → approve») к этому файлу отношения не имеет. Это
   отдельная косметика или часть той же задачи?

## Файлы (предварительно, при уточнении)

- `backend/public/index.php` — одна правка: вставка комментария
  (однострочного `//` или docblock `/** … */`), без изменения логики.
- `docs/plan/plan_<ID>.md` — этот файл, после согласования содержания.

## Шаги (после уточнения)

1. Добавить комментарий в `backend/public/index.php` в согласованном месте.
2. `make lint` (`php -l` по `backend/` и `tests/`) — синтаксис не сломан.
3. Закоммитить отдельным коммитом с message вида
   `docs(<scope>): комментарий в backend/public/index.php`.

## Тесты

Изменение чисто косметическое, без новых тестов. Достаточно убедиться,
что `make test` остаётся зелёным (27/27).

## Риски

- Комментарий в первой строке файла (`<?php`) ломает синтаксис —
  строка с `<?php` должна быть первой в файле. Комментарий ставим
  **после** `<?php` и `declare(strict_types=1);`, как в остальных
  файлах проекта (`backend/src/Domain/DecisionEngine.php` и т.п.).

## Что не входит

- Любые изменения логики, сигнатур, импортов.
- Правки `backend/src/AppFactory.php` и других файлов.
